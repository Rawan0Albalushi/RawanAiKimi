# Requirements

Status: Phase 1 baseline, 21 October 2026. The chat application was added on 22 October 2026 against the RunPod queue. NFR-6 still describes an SSH tunnel for the Pod fallback. The implemented path is the authenticated queue in [architecture.md](architecture.md), which does not meet NFR-6 as originally written.

This document defines what the finished POC must do. It does not authorize implementation. Application code starts in Phase 7, after the planning approval and, for any test that needs the GPU, after the spend approval in the implementation plan.

## Functional requirements

### Chat screen

- **FR-1.** The application shows a single chat screen rendered with React and Inertia.
- **FR-2.** The screen has an empty state before the first message, a visible submitting state while Laravel is waiting on inference, a transcript of the current session, and a visible error state when inference fails.
- **FR-3.** The user can clear the current session transcript from the screen.

### Messages

- **FR-4.** The user can send a text message in Arabic or English, including mixed text.
- **FR-5.** The browser submits the message to a Laravel route. The browser does not call vLLM or any Moonshot URL directly.
- **FR-6.** Laravel validates the message before it is stored or sent to inference. Empty messages are rejected. The POC maximum length is 4,000 characters. This limit is a design default, not a measured model limit.
- **FR-7.** The server accepts Unicode text and does not reject Arabic characters.

### Inference

- **FR-8.** A successful turn returns assistant text generated by the self-hosted `moonshotai/Kimi-VL-A3B-Instruct` checkpoint served by vLLM on the rented GPU.
- **FR-9.** The inference request uses the OpenAI-compatible chat completions API on the private vLLM base URL configured in the environment.
- **FR-10.** The model id, base URL, timeout, and optional API key come from configuration. They are not hardcoded.
- **FR-11.** The UI displays the latency of the inference call for the latest successful or failed turn.
- **FR-12.** When vLLM is unreachable, returns an error, or exceeds the configured timeout, the user sees a clear error and can send another message. The failed call is not presented as assistant text.

### Session context

- **FR-13.** Follow-up messages in the same browser session are sent with the prior user and assistant turns of that session.
- **FR-14.** The transcript lives in the Laravel file session. Closing the session, or clearing the chat, discards it.
- **FR-15.** The server caps how much transcript is forwarded to vLLM so a long browser session cannot request the model’s full 128K context. The numeric cap is chosen in Phase 7 from the context length approved in Phase 2. Until then, the planning assumption is a short POC context, on the order of a few thousand tokens, not 32K or 128K.

### Evidence

- **FR-16.** Test notes record the vLLM model id, a prompt, a completion, the Laravel-measured latency, and a GPU memory sample taken on the server during the test.
- **FR-17.** The final technical report states that the completion was produced on the rented GPU and identifies the evidence used to show that.

## Non-functional requirements

### Architecture

- **NFR-1.** Laravel, Inertia, React, and Vite live in one application. There is no second deployable frontend or backend.
- **NFR-2.** `ChatController` delegates chat behavior to `ChatService`. `ChatService` delegates inference to `KimiService`.
- **NFR-3.** Input validation for the chat message uses a Form Request.
- **NFR-4.** The POC runs with file sessions and file cache. It boots and serves chat without a database connection.
- **NFR-5.** `KimiService` has no knowledge of Inertia, and `ChatService` is callable without an HTTP controller, so a later API controller can reuse both.

### Security

- **NFR-6.** vLLM listens on loopback on the GPU host. The POC path from Laravel is an SSH local forward. An unauthenticated public inference URL is not an acceptable configuration.
- **NFR-7.** Secrets, SSH private keys, RunPod tokens, and `.env` files are gitignored and are never written into documentation.
- **NFR-8.** Web routes keep Laravel CSRF protection.
- **NFR-9.** Logs may contain latency, HTTP status, and a short error summary. Logs must not contain the inference API key.
- **NFR-10.** The GPU host loads the official checkpoint, including its custom modeling code, only from a commit recorded in the Phase 2 notes.

### Reliability and performance

- **NFR-11.** The HTTP client timeout is configurable and is long enough for a short text completion. The planning default is 120 seconds. Phase 9 replaces that default with a value based on measured latency.
- **NFR-12.** A timeout or a 5xx response from vLLM becomes a handled application error, not an uncaught exception page.
- **NFR-13.** The POC is expected to serve one interactive user at a time. Concurrent load is not a requirement.

### Operability and cost

- **NFR-14.** Total cloud charges for the POC stay below 20 OMR.
- **NFR-15.** Every paid action has a written approval that states the maximum spend and the shutdown condition.
- **NFR-16.** After the demonstration, GPU compute is stopped and the final report records the shutdown check. Disk resources are deleted unless the approval says to keep them, because stopped pods can continue to bill for storage.

### Development

- **NFR-17.** The application is developed on Windows with Cursor and Git.
- **NFR-18.** Phase 7 preserves `README.md`, `docs/`, and `.gitignore` when the Laravel skeleton is created in this directory.

## In scope

- Phase 1 documentation, which this repository now holds.
- Later phases described in [implementation-plan.md](implementation-plan.md): compatibility verification, cost validation, a short RunPod rental after approval, vLLM serving the official weights, direct API checks, the unified Laravel chat application, SSH integration, tests, and the POC report.
- Temporary multi-turn text chat in Arabic and English.
- One image with the message that uploads it. JPEG, PNG, and WebP are re-encoded to a private JPEG. Later text turns do not resend it.
- Latency display and a basic GPU memory sample during tests.

## Out of scope

- User registration, login, roles, and Laravel Sanctum.
- MySQL, Redis, and any requirement that the application refuse to boot without a database.
- Permanent chat history.
- Admin screens.
- File uploads other than one chat image, OCR, and video. The live worker still has `--language-model-only`, which disables image inputs. `LIMIT_MM_PER_PROMPT=image=1` is prepared in the repository and is not applied until a separate vision-boot approval.
- Fine-tuning, quantization jobs, and training. Quantization may be investigated as a compatibility alternative in Phase 2. It is not implemented unless a later approval adopts it.
- Publishing vLLM to the public internet.
- Production hosting, CI/CD, autoscaling, and a queue worker for inference.
- Payments, subscriptions, and user quotas.
- Using `api.moonshot.ai` or any hosted chat-completions product as the source of answers.

## Acceptance criteria

The POC is acceptable when all of the following are true:

1. A reviewer can read the architecture and see one Laravel application between the browser and vLLM.
2. On the chat screen, an English message and an Arabic message each receive assistant text, or the report documents a measured model limitation with the raw response still captured.
3. A second message in the same browser session is answered with the previous turn included in the vLLM request. Evidence is a captured request body or an equivalent server-side log of the roles sent, with message text redacted if the report is shared.
4. Clearing the chat removes the transcript from the session. A new message does not include the cleared turns.
5. Stopping vLLM, or pointing the base URL at a closed tunnel, produces the error state within the configured timeout. The application process stays up.
6. The inference base URL used in the successful test is the tunneled private endpoint, and the report records the vLLM model name returned by the server.
7. The report includes at least one latency measurement from Laravel and one GPU memory sample from the host taken while the model was loaded.
8. The report includes the cloud invoice or balance evidence showing total spend below 20 OMR, and a confirmation that compute was stopped.
9. No MySQL server, user table, or login screen was required to complete the demo.
10. Repository history contains no `.env`, private keys, or cloud tokens.

Arabic and English are acceptance inputs. Quality of Arabic generation is not claimed in Phase 1. If the model answers in a degraded way, that result is recorded; it is still a completed inference test.
